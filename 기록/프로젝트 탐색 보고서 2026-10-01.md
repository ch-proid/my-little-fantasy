# 마리판 프로젝트 탐색 보고서

2026-10-01 · 로컬 `main`, 커밋 `97ddbfc` 기준

마리판(My Little Fantasya)은 작업 표시줄 위에서 자동 전투를 보여 주는 픽셀 방치형 RPG다. 캐릭터 생성, 전투, 장비 파밍, 스탯 배분, 슬롯 강화, 어빌리티, 저장, 제작 도구까지 실행되는 프로토타입이다. 특히 캐릭터·장비·몬스터를 직접 고쳐 게임에 반영하는 작업 흐름이 잘 갖춰져 있다.

현재 가장 큰 문제는 방치 보상과 후반 성장 곡선이다. 재접속 보상이 사라지는 오류를 재현했고, 8-10 보스는 강한 시험 장비를 줘도 제한 시간 안에 체력을 거의 깎지 못했다. 가방 표시와 용량 검사도 서로 다르다. 새 콘텐츠를 늘리기 전에 이 부분을 다듬는 편이 좋다.

## 1. 살펴본 범위와 확인 방법

`읽어보기.md`, `CLAUDE.md`, `기록/실수와 교훈.md`, 작업 목록, 세계관, 장비 데이터, 도트 규칙, 창 동작과 이펙트·에셋 변환 기록을 읽었다. 실제 화면에서 불러오는 코드 30개와 게임 상태·전투·메뉴·그리기·창 코드, 데이터와 제작 도구를 살폈다.

실행 시험은 별도 저장소에서 진행했다. Electron은 실제 프로젝트의 창 시작 파일을 실행하지 않고, 숨긴 시험 창에서 게임 HTML을 읽었다. Edge도 화면에 뜨지 않는 시험용 브라우저와 새 프로필을 썼다. 사용자의 기존 게임 저장은 시험 대상에 포함하지 않았다.

| 확인한 항목 | 결과 | 확인 범위 |
|---|---|---|
| JavaScript 34개 문법 검사 | 오류 없음 | 코드·데이터·도구의 JS 파일 |
| 데이터·에셋 JSON 20개 | 모두 읽힘 | 장비, 몬스터 목록, 이펙트 설정 |
| HTML의 외부 스크립트 30개 | 누락 없음 | 현재 게임 HTML |
| 장비 JSON과 브라우저용 JS 복사본 | 내용 일치 | 현재 파일 기준 |
| 8세트 × 장비 PNG 8개 | 64개 모두 있음 | 무기 3종, 방어구 5종 |
| 새 캐릭터 생성, 메뉴 8개 | 실행 성공 | Electron 렌더러와 Edge |
| 저장 내보내기·가져오기 | 상태 일치 | 접속 시각을 제외한 저장 왕복 |
| 무기 3종 × 현재 몬스터 41종 | 123조합 모두 처치 | 스테이지 1, 단독 대상, 무적, 최대 90초 |
| 지역 8개 × 무기 3종 스킬 | 24조합 실행 성공 | 스킬 장면 360회 그리기 포함 |
| 제작 도구 5개 | 모두 초기 화면 실행 | 조작 전체·파일 저장까지 확인한 것은 아님 |

일반 실행에서 JavaScript 예외는 관찰하지 못했다. Edge에서는 로컬 JSON을 읽으려는 요청이 CORS 정책으로 막힌다. 이후 `데이터/장비.js`를 읽어 정상 진행한다. 장비 미리보기에서도 첫 이미지 경로 요청 하나가 실패하지만, 다른 경로를 시도하는 코드가 있다. 이 요청 실패를 곧바로 게임 중단이나 에셋 누락으로 판단하지 않았다.

Windows 창의 층 순서, Win+D, 실제 작업 표시줄 위치, 화면 배율과 여러 모니터에서의 동작은 이번에 직접 시험하지 않았다. Python 변환 도구는 코드를 읽었으며 실제 변환은 실행하지 않았다. 기존 에셋을 재생성하거나 덮어쓰는 작업도 하지 않았다.

시험 결과는 이 문서 옆 `탐색 검증 2026-10-01/`에 남겼다.

- `results.ndjson`: Electron 렌더러, 저장, 방치 보상, 전투와 스킬 시험
- `edge-results.json`: Edge 실행, 초기 진행과 가방 시험
- `tools-results.json`: 제작 도구 5개의 초기 실행 결과
- `late-results.json`: 후반 보스 피해량 시험
- `edge-equip.png`: Edge 장비 화면

## 2. 게임의 방향과 현재 규칙

게임은 작은 전투 띠를 계속 보여 주고, 필요할 때 큰 메뉴를 열어 성장시키는 방식이다. 일반 전투와 이동은 자동으로 돌아간다. 플레이어는 스탯을 배분하고, 얻은 장비를 장착하고, 슬롯을 강화하고, 어빌리티를 뽑는다. 보스에 실패하면 같은 단계에서 반복 사냥으로 바뀌므로 다시 자동 도전을 켜야 한다.

흐름은 `자동 전투 → 골드·경험치·장비 획득 → 성장과 장비 선택 → 보스 도전 → 다음 스테이지`다. 단순히 켜 두기만 하면 모든 성장이 자동으로 적용되지는 않는다.

장비 이름과 능력치 공식은 `데이터/장비.json`이 정한다. 같은 지역 장비는 일반부터 판타지아까지 같은 그림을 쓰며, 등급에 따라 능력치·추가 옵션·공격 이펙트·무기 빛이 달라진다.

스킬 코드에는 검·엽총·완드마다 6개씩 총 18개가 있다. 현재 실제 게임은 지역마다 정한 스킬 하나씩, 총 8개를 사용한다. 다른 종류의 무기를 장착해도 같은 지역 스킬을 무기 동작에 맞춰 변형한다. 판타지아 무기의 재사용 대기시간은 14초다.

세계관은 깨진 ‘판타지아의 심장’ 조각이 여덟 땅의 소원을 뒤틀어 이루었다는 이야기다. 작물이 살아난 밭, 숲에 삼켜진 나무꾼 마을, 잠긴 마을, 얼어붙은 축제 같은 사건을 소품과 몬스터로 보여 주려는 방향이다. 지역마다 장비·색·지형을 묶어 이 방향을 구현하고 있다.

## 3. 코드 구조와 실행 환경

별도의 게임 엔진이나 화면 프레임워크를 쓰지 않는다. HTML·CSS·Canvas·JavaScript로 게임을 만들고, Electron과 koffi로 Windows 창을 다룬다. 설치된 버전은 Electron 44.4.5, koffi 3.3.2다. `package.json`에는 Electron, koffi, galmuri가 선언돼 있다.

| 위치 | 역할과 읽을 이유 |
|---|---|
| `마리판.html` | 화면 틀, 스타일, 스크립트 순서 |
| `코드/게임/data.js` | 전투·성장 수치, 지역, 역할, 등급·장비 데이터 연결 |
| `코드/게임/state.js` | 저장, 상태 보정, 장비 생성·교체·분해, 최종 능력치, 성장, 방치 보상 |
| `코드/게임/combat.js` | 무리 생성, 이동·사거리, 공격, 상태 이상, 보상, 보스·스테이지, 스킬 |
| `코드/게임/render.js` | 전투 화면, 지형, 캐릭터·몬스터, 스킬·이펙트, 화면 표시 |
| `코드/게임/ui.js` | 타이틀, 캐릭터 생성, 메뉴, 장비 비교, 설정·시험 메뉴 |
| `코드/게임/main.js` | 초기화, 시간 처리, 자동 저장, 입력, 전투·그리기 반복 |
| `코드/그림/` | 공용 도트, 캐릭터 합성, 무기 자세, 이펙트, 아이콘·지형 목록 |
| `코드/스킬/` | 18종 스킬의 타격 시각·움직임·그림 |
| `코드/창/` | Electron 창과 게임 화면 사이 연결, Windows 창 순서·크기 |
| `도구/` | 다섯 가지 확인·편집 페이지와 Python 에셋 변환 도구 12개 |

상태 `S`에는 영구 성장과 장비가, `G`에는 현재 전투와 연출이 들어 있다. 메뉴와 전투는 `stats()`로 같은 최종 능력치를 읽는다. 전투는 약 30Hz 타이머로, 그림은 화면 갱신에 맞춰 따로 돌아간다. 그래서 Electron 창이 가려져도 전투를 진행하도록 만들었다. 긴 멈춤은 방치 보상으로 처리하려고 한다.

그림 코드를 게임과 미리보기가 공유하는 점은 강점이다. 에디터에서 이펙트를 바꾸면 공용 공격 연출에도 반영되며, 장비 그림과 공격 자세를 전용 페이지에서 확인할 수 있다. 무기별 동작, 파츠 합성, 그림 캐시, 화면 배율 처리도 이미 있다.

반면 30개 스크립트가 같은 전역 공간을 쓰고, 불러오는 순서로 서로 연결된다. 파일을 나눴지만 의존 관계가 명시적인 모듈 구조는 아니다. `실수와 교훈.md`에도 전역 이름이 겹쳐 실행이 멈춘 사례가 여러 번 기록돼 있다. 상태 함수가 그림·메뉴를 부르는 곳도 있어 규칙만 따로 시험하기가 쉽지 않다. 당장 전부 다시 쓰기보다 저장·보상·능력치 계산부터 독립적으로 확인할 수 있게 만드는 편이 좋다.

Windows 띠 창은 480×121이며, 일반 메뉴는 위쪽으로 400만큼 늘고 전체 너비가 760으로 바뀐다. 전투 캔버스 논리 크기는 480×110이고 나머지는 경험치 막대다. 기본 화면의 아래 층 유지와 Win+D 대응에는 `user32.dll`을 쓴다. 현재 데스크톱 실행은 Windows를 전제로 한다.

`게임 실행.cmd`는 폴더 안 Electron 실행 파일을 직접 연다. `npm start`도 같은 앱을 실행한다. 설치 파일을 만드는 설정, 배포용 빌드 명령, 저장소에 있는 자동 테스트나 CI 구성은 찾지 못했다. 현재는 개발 폴더를 실행하는 방식이다. 브라우저와 Electron의 저장소는 서로 다르다.

## 4. 에셋과 제작 흐름

이전판·손질원본·사용자 수정 사본을 제외한 현재 PNG 수는 다음과 같다. 참고 이미지와 공유 압축 파일은 포함하지 않았다.

| 종류 | PNG 수 | 실제 연결 방식 |
|---|---:|---|
| 몬스터 | 41 | PNG와 목록을 변환해 `mon_assets_*.js`에 글자 지도·색·움직임 정보로 저장 |
| 캐릭터 파츠 | 29 | 몸 1, 헤어 11, 상의 4, 하의 3, 코스튬 10. `art.js`에 변환해 합성 |
| 지역 장비 | 64 | 8세트 × 무기 3·방어구 5. 무기는 PNG 직접 읽기, 방어구는 캐릭터 코드에 반영 |
| 지형 | 95 | PNG 직접 읽기, `terrain_list.js`가 분류·그림 위치·크기를 제공 |
| 공격 모션 | 120 | 8세트 × 무기 3 × 프레임 5. 현재 게임은 공용 자세 코드로 동작 |
| 아이콘 | 8 | 변환 후 `icons.js` 사용 |
| 이펙트 | 11 | 설정 JSON과 시트 PNG. 게임은 설정으로 프레임을 생성 |

몬스터 등록 객체에는 50종이 있지만 현재 지역 목록에서 실제 등장하는 것은 41종이다. 파일 안 정의 수와 현재 콘텐츠 수를 구분해야 한다. 캐릭터 파츠 틀은 현재 24×28칸이다. 주요 캐릭터·몬스터·무기는 한 칸을 화면 2px로 그린다.

몬스터는 통통 뛰기·걷기·무거운 걸음·벌레 다리·날갯짓·흉내쟁이 등 몸에 맞는 움직임을 가진다. 사람이 고친 PNG는 `raw`로 읽어 색을 그대로 보존한다. 캐릭터는 파츠를 합성하고 걷기나 엽총 두 손 자세를 만든다. 지형은 먼 배경·가까운 소품·작은 장식·바닥으로 나눠 서로 다른 속도로 흐른다.

에셋을 고친 뒤 게임에 반영하는 방법이 종류마다 다르다.

- 캐릭터·방어구: PNG 수정 후 `주인공.py 넣기`.
- 몬스터: PNG와 해당 지역 `목록.json`을 바탕으로 `PNG넣기.py`를 실행하고, HTML의 묶음 파일 연결을 유지.
- 무기: PNG를 직접 읽으므로 다시 불러오면 그림이 바뀜. 외곽 크기와 쥐는 위치의 규칙은 유지해야 함.
- 지형: PNG 그림을 읽으며 목록에 잘라 그릴 위치·크기가 고정돼 있음. 그림 범위·이름·종류가 바뀌면 `지형넣기.py`도 다시 실행해야 함.
- 아이콘: PNG 수정 후 `아이콘넣기.py`.
- 장비 데이터: JSON 수정 후 Electron 실행 또는 `장비넣기.py`로 JS 복사본 갱신. 브라우저만 쓰면 직접 갱신이 필요함.
- 이펙트: 에디터에서 JSON·시트를 저장하고 목록을 갱신. 폴더에 직접 저장할 수 없는 브라우저는 파일을 받아 옮긴 뒤 `이펙트넣기.py`.

원본 PNG와 게임에 쓰는 코드가 함께 있으므로, 현재처럼 변환 방법을 알고 있을 때는 작업하기 편하다. 다만 새 개발자는 PNG만 고치고 게임에 반영됐다고 착각하기 쉽다. 도구마다 필요한 Python 패키지(Pillow·일부 도구의 NumPy)를 설치할 공통 의존성 파일도 찾지 못했다. 변환 명령과 결과 파일을 한곳에 정리하고 원본·생성 파일이 일치하는지 검사하면 작업 실수를 줄일 수 있다.

## 5. 재현한 문제와 우선순위

### 우선: 재접속 방치 보상 소실

근거: `코드/게임/main.js:32`, `main.js:37`, `코드/게임/state.js:29`, `state.js:217`.

1시간 전 시각이 들어 있는 정상 저장을 시험 저장소에 넣고 페이지를 다시 불렀다. 타이틀에서 접속 시각의 나이는 약 0.022초로 줄었고, 이어하기를 눌러 얻은 골드는 0이었다. 방치 보상 함수를 1시간 전 상태에서 직접 부르면 골드 901과 경험치 1,803을 주므로, 보상 계산 자체와 재접속 경로의 동작이 다르다.

초기화에서 보상 전에 `save()`를 불러 `lastSeen`을 지금으로 바꾼다. 타이틀 중에도 타이머가 이 값을 계속 바꾼다. 이전 접속 시각을 보상 정산까지 보존하고, 정산이 끝난 뒤 현재 시각을 저장해야 한다. ‘1시간 비운 척’ 시험 단추만 눌러서는 이 오류를 발견하기 어렵다.

### 우선: 후반 성장 곡선

근거: `코드/게임/data.js:21`의 몬스터 체력 성장, `코드/게임/state.js:100`의 장비 기본 옵션, `코드/게임/combat.js:24`의 보스 체력 배율.

몬스터 체력은 단계마다 1.155배가 되지만 장비 기본 옵션은 단계에 따라 일정량 늘어난다. 80단계 기본 몬스터 체력은 약 123만, 보스 체력은 약 1,969만이다. 해당 단계 판타지아 무기 공격력은 280이며, 30강을 적용한 기본 공격력은 784다. 캐릭터 스탯·추가 옵션·스킬을 더하더라도 성장 속도 차이를 따로 검증해야 한다.

후반 시험에서는 100레벨, 스탯 297점을 모두 힘에 배분하고, 80단계 판타지아 장비 9개와 모든 슬롯 30강을 줬다. 모든 장비에 높은 데미지·치명타·치명타 피해·힘 옵션을 넣고, 장신구는 공격력과 명중을 주었다. 어빌리티는 30레벨에 높은 데미지·공격 속도·힘 옵션을 줬다. 무적으로 생존 문제를 제거하고 보스를 가까이 세운 뒤, 게임 시간 30초 동안 공격하게 했다.

| 무기 | 화면 계산상 예상 초당 피해 | 30초간 보스 체력 감소 |
|---|---:|---:|
| 검 | 27,362 | 0.79% |
| 엽총 | 27,600 | 1.77% |
| 완드 | 20,343 | 0.74% |

무기 3종 모두 보스를 처치하지 못했다. 이 설정이 가능한 모든 조합의 최적값이라는 뜻은 아니며, 무작위 피해의 단일 표본이다. 그러나 상당히 유리한 조건에서도 큰 차이가 나므로 후반 진행을 보장할 성장 수치가 필요하다. 지역마다 목표 도달 시간과 장비·레벨 수준을 먼저 정하고, 보스 처치 시간·사망·강화 비용·경험치 시간을 함께 맞추는 것이 좋다.

### 다음: 방치 경험치 보너스 중복

근거: `코드/게임/state.js:173`, `state.js:212`, `state.js:221`.

`idleRates()`에서 경험치 보너스를 곱하고, 그 결과를 `addExp()`에 넘길 때 다시 곱한다. 경험치 +15%로 시험했을 때 표시 보상은 2,073이었지만 실제 누적 경험치는 2,383.95였다. 표시량보다 다시 15% 많았다. 보너스와 반올림을 적용할 곳을 하나로 정해야 한다.

### 다음: 가방 개수 표시와 실제 용량 불일치

근거: `코드/게임/ui.js:269`, `코드/게임/state.js:120`.

가방 화면은 전체 보유 개수에서 장착 슬롯 개수를 빼서 표시한다. 획득 함수는 장착 장비를 포함한 전체 개수를 60과 비교한다. 장비 9개를 착용하고 전체 60개를 가진 시험에서는 화면 기준 `51 / 60`인데도 새 장비를 골드로 바꿨다. 장착 장비가 가방 용량을 차지하는지 정하고 두 계산을 맞춰야 한다.

### 다음: 가방 초과 시 판타지아도 분해

근거: `코드/게임/ui.js:281`, `코드/게임/state.js:118`.

## 6. 플레이 흐름과 파밍에서 보이는 점

초기 무기만 들고 장비 교체·강화·스탯 배분 없이 15분 분량을 계산한 결과는 다음과 같다. 무적은 껐다. 난수를 고정하지 않은 무기별 한 번의 시험이며 실제 15분 동안 창을 켜 둔 장시간 시험은 아니다.

| 무기 | 도착 단계 | 레벨 | 처치 | 미사용 스탯 점수 | 마지막 모드 |
|---|---|---:|---:|---:|---|
| 검 | 1-1 | 11 | 250 | 30 | 반복 사냥 |
| 엽총 | 1-5 | 14 | 286 | 39 | 반복 사냥 |
| 완드 | 1-2 | 12 | 264 | 33 | 반복 사냥 |

초반에도 무기별 진행 차이가 있었고, 골드·레벨을 얻는 동안 쓰지 않은 성장 자원이 쌓였다. 이는 조작 오류를 뜻하지 않는다. 현재 게임은 자동 전투와 수동 성장의 조합이므로, 처음 보스에 막혔을 때 스탯 배분·장비 교체·강화·재도전을 알려 주는 안내가 도움이 될 수 있다. 무기별 목표 보스 처치 시간도 같은 기준으로 비교할 필요가 있다.

판타지아 드롭 비중은 일반 장비 드롭에서 0.2%, 보스 장비 드롭에서 2%다. 이 수치가 곧 몬스터 한 마리당 판타지아 무기 확률은 아니다. 일반 몬스터 장비 드롭 9%, 장비 종류에서 무기 비중 2/9를 함께 적용하면 판타지아 무기는 처치당 약 0.004%다. 보스는 장비를 두 번 떨어뜨리므로 판타지아 무기를 적어도 하나 얻을 확률은 약 0.887%다. 모두 현재 코드의 독립 추첨 규칙으로 계산한 값이다. 목표 획득 시간을 논의할 때 이 실제 확률을 써야 한다.

방치 수익 계산도 적 체력·예상 초당 피해·무리 수·걷는 시간을 어림하며 명중 실패, 적 방어, 역할별 체력, 사망, 보스, 스킬을 직접 계산하지 않는다. 따라서 온라인 수익의 정확한 50%라고 보기 어렵다. 검의 방치 범위 계수는 최대 3인데 실제 검 공격은 닿는 적 수에 제한이 없어 무기 사이 오차도 생길 수 있다. 재접속 오류를 고친 뒤 실제 반복 사냥 수익과 비교해 보정할 부분이다.
